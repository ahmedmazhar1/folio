Folio API v1

Catalogue guides and our own packaging mockup engine. No Pacdora account or key is required.

This version supports catalogue browsing, guide estimates and visual mockups. It does not accept orders or payments, send quote briefs, or provide paid API authentication and licensing.

Endpoints

Method / pathPurpose
GET /api/v1/healthService status. Suitable for a container health check.
GET /api/v1/productsCatalogue products, options, pack sizes and price sources; currency is PKR.
POST /api/v1/catalogue/estimateValidate a quote list and calculate authoritative guide totals.
GET /api/v1/templatesPrototype template IDs, default dimensions, materials and limits.
POST /api/v1/configurations/validateValidate a packaging configuration and normalize dimensions to millimetres.
POST /api/v1/estimatesCustom packaging quote requirement. Returns PKR with unit_price: null, total: null and quote_required: true.
POST /api/v1/dielinesReview SVG; not a certified production die.
POST /api/v1/sizing/recommendProduct dimensions plus an adjustable clearance allowance.
POST /api/v1/modelsPanel hierarchy, outlines, hinges, thickness, fold phases and printable faces.
POST /api/v1/models/posePanel angles for progress from 0 (closed) to 1 (flat).
POST /api/v1/recommendationsRule-based template recommendation from a product description and optional dimensions. No AI provider is connected.

Catalogue guide estimate

Get product IDs and options from /api/v1/products, then submit only configuration choices. The server reads its own catalogue and ignores client-supplied prices.

{
  "items": [
    {
      "productId": "custom-logo-stickers",
      "optionIndex": 0,
      "quantity": 1,
      "customPrint": false
    }
  ]
}

The product ID above is an example; use the current catalogue IDs. quantity is the number of selected packs. unitsPerPack and unitPrice come from the server. The calculation is quantity × units per pack × PKR per physical item. One pack of 50 at PKR7 each has a guide total of PKR350.

A null price or customPrint: true requires a quote and gives that line a null guideTotal. The subtotal includes priced lines only. hasUnpriced and quoteRequired flag a partial total. Source URLs, checked dates and price basis accompany the lines. Quantities must be whole numbers satisfying the selected option’s minimum and step, up to 100,000. A request supports 1–100 lines.

These are research-based guide prices pending merchant confirmation. Tax, shipping, custom printing, artwork/setup and discounts are not confirmed. An estimate is neither an order nor an invoice.

Packaging configuration

Send JSON with Content-Type: application/json. Units are mm or in. Converted limits are L 100–400, W 80–300 and H 30–200 mm. Materials: kraft, sbs, rigid. Finishes: matte, gloss, soft. Supported quantities: 100, 250, 500, 1000, 2500, 5000.

{
  "template_id": "mailer",
  "dimensions": {"L": 220, "W": 150, "H": 60},
  "unit": "mm",
  "material": "kraft",
  "finish": "matte",
  "quantity": 500
}

Read the current 16 template options from /api/v1/templates. Models use nominal preview dimensions; usable internal space and board allowances are not verified.

Folding engine

Open the integration example. It loads a model through the API and drives its folds with the reusable browser renderer.

// THREE is supplied by the host application.
const response = await fetch('/api/v1/models', {
  method: 'POST', headers: {'Content-Type':'application/json'},
  body: JSON.stringify({template_id:'mailer', dimensions:{L:220,W:150,H:60}})
});
const box = FolioFolding.mount(THREE, await response.json());
scene.add(box.group);
box.setProgress(0.5); // partially unfolded
box.dispose(); // release resources when removing the box

Renderer: /folding-engine.js. Panel schema 1.0; API v1. Models and dielines are visual mockups with no collision, physical-fit or manufacturing guarantee.

Sizing request

{
  "product": {"L": 210, "W": 140, "H": 50},
  "unit": "mm",
  "clearance_mm": 4
}

Returns a target internal size of 214 × 144 × 54 mm. Clearance is the total addition per dimension, not per side. Physical packaging fit still needs validation.

Hosting and access

The server defaults to 127.0.0.1:4173. Set HOST and PORT for hosting; the included Dockerfile uses 0.0.0.0:8080. Place HTTPS at the host or reverse proxy and preserve the original Host header. Browser POST origins must match that host. External origins are rejected, and cross-origin access headers are not sent. Command-line requests without an Origin header are allowed. This check does not authenticate API customers.

The catalogue and downloadable briefs can be hosted as a preview. Actual customer accounts, supplier connections, order storage, payments, shipping, paid API keys, quotas, billing and license enforcement are not implemented. Public commercial API access needs those services and production hosting controls.

Errors

422 invalid JSON, configuration or catalogue choice; 413 body size limit; 415 wrong content type; 403 external browser origin; 404 unknown route. Responses include error and message. Maximum request body: 32 KiB.

curl http://localhost:4173/api/v1/products

curl http://localhost:4173/api/v1/estimates \
  -H 'Content-Type: application/json' \
  -d '{"dimensions":{"L":220,"W":150,"H":60},"quantity":500}'
